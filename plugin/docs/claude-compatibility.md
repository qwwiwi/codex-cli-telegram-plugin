# Перенос настроек с Claude Code

## Отдельные вопросы во время работы

Укажите `KROT_CODEX_SIDE_REPLY=1`. При занятой задаче сообщение «Отдельный вопрос: что такое JSON?» может получить ответ в отдельном временном сеансе. Для самостоятельного ответа без основного хода отдельному сеансу доступен текст вопроса и краткое состояние плана. Если ответа по этим данным нет, вопрос уходит в обычную очередь. Для обычных уточнений мост сначала использует основной ход, когда он принимает ввод. Временному сеансу нужен локальный Codex CLI с входом через ChatGPT под пользователем моста. Внешние обращения, пересылки и цитаты не запускают отдельный сеанс.

## Ответ параллельно, пока идёт долгая задача

Укажите `KROT_CODEX_PARALLEL=1`. Пока основной поток работает над задачей, новое сообщение получает ответ сразу: его берёт второй, параллельный поток Codex в том же процессе. Он знает, чем занят основной поток (название задачи, текущий шаг плана, сколько она уже идёт), отвечает сам и при необходимости может выполнить отдельную долгую задачу. Ответ приходит цитатой на ваше сообщение.

Куда попадёт сообщение, пока основная задача идёт:

1. Ответ (reply) на сообщение параллельного разговора продолжает этот же параллельный поток.
2. Любой другой ответ (reply) уходит в текущую основную задачу как уточнение, как раньше.
3. Сообщение, которое начинается со слова-уточнения, тоже уходит в основную задачу. По умолчанию это «уточнение», «поправка», «к задаче», «стоп». Свой список задаётся через `KROT_CODEX_CORRECTION_WORDS=слово1,слово2`. Слово должно стоять целиком: «стопка» не считается.
4. Всё остальное получает новый параллельный поток.

`KROT_CODEX_MAX_PARALLEL` ограничивает число потоков вместе с основным (от 1 до 8, по умолчанию 2: основной и один параллельный). Когда все потоки заняты, сообщение встаёт в обычную очередь, и мост пишет, что сейчас выполняется. Очередь разбирает основной поток после своей задачи.

Ограничения. Потоки работают в одной рабочей папке; параллельному потоку сказано не трогать файлы основной задачи, других блокировок нет. Статус-пузырь и HUD показывают только основную задачу, параллельный поток отмечается реакцией 👀 и ответом. `/stop` останавливает оба потока. Если мост или Codex перезапустится во время параллельного ответа, этот ответ теряется: отправьте сообщение ещё раз. Альбомы по-прежнему уходят в основную задачу. Чтобы вернуть прежнее поведение, уберите `KROT_CODEX_PARALLEL` или поставьте `0`.

### Кеш промпта

Модель каждый раз перечитывает весь диалог. Если начало запроса совпадает с прошлым, OpenAI берёт его из кеша: быстрее и в разы дешевле для лимита. Поэтому мост бережёт это начало:

- Новый параллельный поток для сообщения владельца — это ответвление основного диалога (`thread/fork` с `ephemeral: true`), а не пустой диалог. Он сразу знает историю основной задачи и попадает в уже прогретый кеш. Ответ (reply) в параллельный разговор продолжает то же ответвление. Ответвление временное: после перезапуска моста или Codex продолжить его нельзя, сообщение уйдёт в новый поток.
- Сообщения других агентов (webhook) основной диалог не ответвляют: их параллельный поток всегда начинается с нуля, чтобы чужой агент не получил историю владельца.
- Если Codex или root relay отказали в ответвлении, мост пишет в журнал строку `Codex refused thread/fork for a side thread; side threads use thread/start from now on` и до перезапуска открывает параллельные потоки по-старому, с нуля.
- Модель передаётся в ход только когда она поменялась (`/cc model`). Смена модели всё равно сбрасывает кеш: следующий ответ прочитает диалог по полной цене.

HUD показывает долю кеша последнего запроса основного диалога рядом с контекстом: «🧠 Контекст: ▰▰▱▱▱▱▱▱▱▱ 21% (54k / 258k) · кеш 82%». Норма в живом диалоге — 80–90% и выше со второго сообщения. 0% посреди диалога значит, что кеш сброшен: пауза дольше 30 минут, смена модели или сжатие (`/cc compact`). Если Codex не прислал счётчик кеша, HUD его просто не показывает.

Настройки `watcher` управляют отдельным уведомлением о занятости. Мост отвечает с цитатой входящего сообщения, учитывает паузу между уведомлениями и продолжает обрабатывать сообщение.

## Действия в Telegram

В новых сессиях Codex получает результат отправки, редактирования, реакции или скачивания вложения прямо из инструмента `telegram_action`. Codex регистрирует инструмент при создании сессии. В ранее созданных сессиях сохраняется служебный способ передачи действий. Команда `/new` создаёт сессию с инструментом.

## Пользовательские команды

Укажите абсолютный путь к доверенному каталогу `KROT_CODEX_COMMANDS_DIR`. Файл `team/report.md` открывается как `/cc team:report аргументы` или `/team:report аргументы`. Мост подставляет аргументы в `$ARGUMENTS` и передаёт получившийся текст как обычную задачу Codex. Подстановки команд оболочки и плагины Claude этим механизмом не запускаются.

## Мандат из карточки вопроса

При включённом `ask_user_question.enabled` агент может начать вопрос с `[LEASE: точная задача; ttl=24h]` и предложить «Да» и «Нет». В карточке показаны весь объём мандата и срок. Мандат выдаётся по подтверждающей кнопке в личке владельца. Текстовый ответ, «Нет», отмена и множественный выбор мандат не выдают. Разрешения Codex по-прежнему действуют.

Если срок вопроса истёк, мост убирает кнопки и сохраняет вопрос для существующего механизма напоминаний. После перезапуска карточка сохраняет вопрос и варианты. Старый запрос Codex уже закрыт, поэтому карточка предлагает отправить уточнение новым сообщением.

## Профиль разрешений YAML

Мост использует прежний классификатор `allow/confirm/deny` через хук Codex `PreToolUse`. `deny` останавливает вызов, `confirm` отправляет карточку, `allow` проходит к обычной проверке песочницей. Карточка Bash или `apply_patch` может покрыть одно последующее разрешение Codex для той же операции. Мост сверяет обе команды или пути и изменения в файлах. Если оба запроса описывают разные действия или представления правки невозможно однозначно сверить, появляется новая карточка. Для повторного использования решения нужны обновлённые сборки моста и хука.

Нативные запросы могут приходить от субагента текущей задачи. Мост подтверждает его связь с диалогом через App Server и сверяет ход выполнения. Карточка сетевого доступа показывает адрес назначения, а карточка ввода в терминал — ID процесса и передаваемый текст. Решение действует один раз. При развёртывании через root relay для этого нужна актуальная версия скрипта `scripts/codex-root-relay.py`.

1. Соберите хук из каталога `plugin/` командой `bun build scripts/codex-permission-hook.ts --target bun --outfile codex-permission-hook.js`. Установите сборку и прежний YAML в защищённый каталог, которым управляет администратор.
2. Для правил `confirm` настройте локальный webhook моста и `KROT_CODEX_APPROVALS=1`. Задайте отдельный случайный `KROT_CODEX_POLICY_TOKEN` в окружении службы моста. Тот же токен запишите в отдельный файл для процесса Codex с правами `0600`. Используйте разные токены для команды и выдачи карточки. Обработчик карточек доступен только на loopback.
3. Добавьте хук с командой вида `/absolute/bun /absolute/codex-permission-hook.js /absolute/permission-policy.yaml 8092 /absolute/policy-token` в конфигурацию Codex App Server. Для хука установите тайм-аут 135 секунд. Подтвердите доверие изменённому хуку через интерфейс Codex. Сначала проверьте `deny` и `confirm` на безопасных контрольных командах.

Четвёртый аргумент после имени скрипта выбирает область из `scopes` в YAML. По умолчанию используется `main`. Если явно указать область, которой нет в файле, хук откажет в вызове. После перезапуска моста кнопки оставшихся карточек убираются. Запрос от завершившегося процесса нужно открыть заново.

Старые `SessionStart`, `PreCompact`, `PostToolUse` и `Stop` обслуживали память, статус и доставку через процесс Claude. Эти функции в мосту привязаны к событиям Codex App Server. `/keys` управляет сессией через Telegram, `/mirror` показывает вывод, относящийся к работе. [Документация Codex о хуках](https://learn.chatgpt.com/docs/hooks)
