# Как агент учится из переписки

Добавьте `KROT_CODEX_LEARNING=1` в `plugin/.env` и перезапустите мост. После каждых десяти завершённых ответов в личке отдельный временный сеанс Codex разбирает последние пары сообщений. Новый запрос пользователя не ждёт окончания разбора. Команда `/memory review` запускает его сразу, если накопились сообщения. Для журнала диалога можно независимо оставить текущие настройки.

Локальный Codex CLI должен быть доступен пользователю моста и показывать вход через ChatGPT в `codex login status`. Для фонового разбора требуется App Server с поддержкой временных потоков без рабочего окружения и структурированного вывода. Если основной диалог подключён через `KROT_CODEX_PROXY`, разбор всё равно использует отдельный **локальный** App Server пользователя моста. В такой установке вход через прокси относится к основному диалогу, а для разбора нужен вход под пользователем моста. Разбор расходует лимит этого аккаунта.

## Что сохраняется

| Запись | Пример | Когда применяется |
|---|---|---|
| Предпочтение | Начинай отчёт с результата, потом детали | В следующих поручениях, в том числе после `/new` |
| Рабочий урок | Сравни результаты проверок до и после правки | В следующих поручениях, если относится к задаче |
| Навык | Порядок проверок перед выпуском версии | Когда текст задачи содержит одну из заданных для навыка фраз |

Плагин хранит записи в приватном каталоге `$TELEGRAM_STATE_DIR/learning` и создаёт файлы для просмотра `USER.md`, `MEMORY.md` и `skills/<id>/SKILL.md`. Источник данных для плагина — `learning.json`. Для изменения записей пользуйтесь командами Telegram. Подтверждённые записи подхватываются на следующем поручении. Команды, сообщения из внешнего вебхука, пересылки и содержимое вложений не попадают в выборку входящих сообщений для разбора. Узнаваемые секреты маскируются перед передачей модели.

## Управление из Telegram

- `/memory pending [страница]` показывает предложения и их ID.
- `/memory approve user/reports` добавляет предложенное предпочтение или заменяет его предыдущую версию.
- `/memory reject ID` отклоняет предложение.
- `/memory list [страница]` показывает сохранённое.
- `/memory forget ID` удаляет сохранённую запись.

По умолчанию все записи ждут подтверждения. С `KROT_CODEX_LEARNING_AUTO_SAVE=1` предпочтения, уроки и навыки добавляются и обновляются автоматически, без сообщений от фонового разбора. Уже полученные предложения можно посмотреть через `/memory pending`. Если разбор заново предложит изменение той же записи, оно сохранится автоматически и заменит старое предложение. При заполнении хранилища обновления имеющихся записей продолжаются. Место для новой записи можно освободить через `/memory forget`.

`KROT_CODEX_LEARNING_INTERVAL` задаёт интервал в завершённых обменах от 1 до 30. `KROT_CODEX_LEARNING_MODEL` позволяет выбрать отдельную модель из доступных в аккаунте. Фоновый сеанс получает только текст выбранных обменов, работает без подключённых инструментов и возвращает предложения для проверки. Сохранённые записи не меняют права доступа, подтверждения и инструкции агента.

Реализация использует тот же тип временного структурированного сеанса, что и [Codex CLI](https://github.com/openai/codex/blob/main/codex-rs/tui/src/temporary_structured_request.rs).
