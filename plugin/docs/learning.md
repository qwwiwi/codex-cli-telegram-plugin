# Память Codex Brain

Brain включён по умолчанию. Мост хранит журнал диалога, факты и открытые задачи в приватном каталоге `$CODEX_HOME/brain` (обычно `~/.codex/brain`). Секреты маскируются до записи. Факты и задачи входят в снимок памяти при создании или сжатии диалога. Новую запись можно открыть сразу через `/memory` или `brain show <id>`.

Запись от имени владельца может возникнуть из текста, который он написал в личном чате с ботом, из подписи к его фото или документу, или из подтверждённой там расшифровки голосового. Ответ на сообщение остаётся словами владельца: в журнал идёт только его текст, а не цитируемое сообщение. Пересылки, вставленные цитаты и сообщения от агентов обрабатываются отдельно и могут дать только предложения на проверку. Неподтверждённое голосовое идёт в основной диалог, но без права записи. При сохранении из текущего диалога бот показывает «Сохранено» и кнопку «Забыть». Для каждого такого хода мост выдаёт модели одноразовый ключ хода: записать факт может только команда `brain` с этим ключом. Другая сессия Codex, терминал или фоновая задача без ключа получают только предложение на проверку. Ключ не попадает в журнал и вычищается из ответов.

## Команды личного чата владельца

| Команда | Действие |
| --- | --- |
| `/memory` | Состояние Brain, размер журнала, доверие к хукам и последняя передача контекста |
| `/memory list [вид] [страница]` | Список записей с кнопками |
| `/memory show <id>` | Текст, источник и ревизия записи |
| `/memory add <текст>` | Сохранить факт |
| `/memory edit <id> [r<ревизия>] <текст>` | Изменить указанную ревизию |
| `/memory forget <id>` | Запросить подтверждение удаления |
| `/memory pin <id или текст>` | Закрепить существующую или новую запись |
| `/memory tasks`, `/memory done <id>` | Показать открытые задачи или закрыть одну |
| `/memory pending [страница]` | Просмотреть, принять или отклонить предложения |
| `/memory search <слова>` | Искать по фактам и журналу |
| `/memory day [ГГГГ-ММ-ДД]` | Открыть дневной дайджест |
| `/memory handoff` | Открыть последний переданный контекст сжатия |
| `/memory off`, `/memory on` | Выключить или включить Brain |

Устаревшая кнопка удаления оставляет текущую ревизию без изменений. После удаления начните новый диалог через `/new`, чтобы загрузить обновлённый снимок.

Без доверенных хуков или обработчика PreCompact в статусе виден `degraded: no handoff inside a turn`. Мост подставляет снимок в первый подходящий ход и после сжатия, на следующем ходе владельца. Строка Brain в `/doctor` показывает состояние хуков. Новый диалог бота получает снимок от моста в первом ходе, если хук его не дал. Старый диалог владельца, созданный до Brain, регистрируется при возобновлении и получает снимок в следующем ходе. Терминальная сессия Codex, начатая в ту же минуту, не может забрать себе память владельца.

## Переход со старой памяти

Мост один раз переносит записи из `$TELEGRAM_STATE_DIR/learning/learning.json` в очередь проверки `/memory pending`: и предложения, и «одобренные» записи, потому что старая память не хранила доказательства, что их одобрил владелец (их мог сохранить автоматический разбор). Запись, которую нельзя сохранить, пропускается с предупреждением в журнале, а оставшиеся пары сообщений в журнал с происхождением старых данных. Старые команды `/memory pending`, `approve`, `reject` и `forget` понимают перенесённые записи и прежние идентификаторы вида `user/reports`.

`/memory off` сохраняет выбор в `$CODEX_HOME/brain/config.json` на будущие запуски и обновления. Мост снова использует настроенные ранее механизмы старой памяти. Начните новый диалог, чтобы убрать уже загруженный снимок из контекста Codex.
