# Установка Krotov Plugin на VPS с нуля

Быстрый путь после подготовки VPS и входа в Codex — `./install.sh --start` из корня репозитория. Чтобы поручить установку агенту, отправьте ему ссылку на [инструкцию для агента](../../INSTALL-WITH-AGENT.md). Ниже описана ручная установка и диагностика.

Подойдёт Ubuntu или Debian с systemd. Нужен обычный пользователь VPS с доступом к `sudo`, аккаунт ChatGPT с доступом к Codex, Telegram и право чтения репозитория. Все шаги установки выполняйте в Bash от одного и того же обычного пользователя.

Если на сервере доступен только `root`, создайте обычного пользователя средствами вашей системы и войдите под ним перед установкой. Имя пользователя выбираете вы.

## 1. Установите инструменты и скачайте репозиторий

```bash
sudo apt update
sudo apt install -y ca-certificates curl gh git jq nano unzip
```

Установите Bun и Codex CLI по их официальным инструкциям. Если обе команды уже доступны в терминале, проверьте версии. [Bun](https://bun.com/docs/installation) · [Codex CLI](https://learn.chatgpt.com/docs/codex/cli)

```bash
bun --version
codex --version
```

Для приватного репозитория войдите в GitHub под аккаунтом, которому дали доступ. Откройте показанную GitHub CLI ссылку в браузере на своём компьютере и введите одноразовый код. Для публичного репозитория можно начать с `read`.

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com
read -r -p 'Ссылка на ваш репозиторий Krotov-plugin: ' krotov_repo_url
git clone -- "$krotov_repo_url" "$HOME/Krotov-plugin"
cd "$HOME/Krotov-plugin/plugin"
bun install --frozen-lockfile
```

[Вход в GitHub CLI](https://cli.github.com/manual/gh_auth_login)

## 2. Войдите в Codex через ChatGPT

В настройках безопасности ChatGPT включите вход по коду устройства. Для рабочего аккаунта доступность опции может зависеть от администратора. Выполните на VPS первую команду и откройте ссылку из терминала в браузере на своём компьютере. Войдите в свой аккаунт и введите одноразовый код. Затем проверьте статус второй командой.

```bash
codex login --device-auth
codex login status
```

CLI должен сообщить, что выполнен вход через ChatGPT. Если вход по коду недоступен, [в документации Codex](https://learn.chatgpt.com/docs/auth#login-on-headless-devices) описаны варианты для VPS без браузера. Токены входа и файл `~/.codex/auth.json` храните в секрете.

## 3. Создайте бота и найдите числовые ID

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и задайте имя и уникальное имя пользователя. Сохраните выданный токен.
2. Откройте **личный чат своего нового бота** и нажмите **Start**. Мост ещё не запущен, поэтому бот пока молчит.
3. В том же терминале выполните команды ниже. Когда терминал попросит токен, вставьте его и нажмите Enter. Ввод не отображается. После команды `getMe` сверьте выведенный `username` с именем бота, которое выбрали в BotFather.

```bash
read -rs -p 'Токен нового бота: ' KROTOV_BOT_TOKEN
printf '\n'
telegram_api() {
  printf 'url = "https://api.telegram.org/bot%s/%s"\n' "$KROTOV_BOT_TOKEN" "$1" |
    curl --silent --show-error --fail --max-time 15 --config -
}
telegram_api getMe | jq -e 'select(.ok) | .result | {bot_id: .id, username}'
```

4. Выполните первую команду ниже, скопируйте напечатанную строку и отправьте её боту в личку. Затем выполните остальные команды. `owner_user_id` и `private_chat_id` должны быть одинаковыми. Если вместо результата пусто, убедитесь, что строка отправлена именно этому боту, и повторите запрос, пока функция и переменная ещё доступны.

```bash
krotov_probe="krotov-$(cat /proc/sys/kernel/random/uuid)"
printf '%s\n' "$krotov_probe"
```

```bash
telegram_api getUpdates | jq -e --arg probe "$krotov_probe" '
  first(.result[] | .message | select(.chat.type == "private" and .text == $probe)
    | {owner_user_id: .from.id, private_chat_id: .chat.id})
'
```

Когда записали все три ID, очистите переменные и функцию.

```bash
unset KROTOV_BOT_TOKEN krotov_probe
unset -f telegram_api
```

Эти команды рассчитаны на нового бота. Если переиспользуете старого, сначала остановите его прежний процесс и проверьте, что webhook отключён. Telegram разрешает только один процесс polling на токен. Метод `getUpdates` здесь нужен только для настройки, дальше обновления читает мост.

[Создание бота в Telegram](https://core.telegram.org/bots/features#botfather) · [Telegram Bot API](https://core.telegram.org/bots/api#getting-updates)

## 4. Заполните настройки

Узнайте абсолютный путь к домашней папке. Создайте отдельные рабочую папку и папку состояния. Затем откройте `.env` с правами чтения и записи только для своего пользователя. Команда `test` сохраняет уже существующий `.env`, если вы повторяете этот шаг.

```bash
printf '%s\n' "$HOME"
install -d -m 700 "$HOME/.local/state/krotov-plugin" "$HOME/krotov-workspace"
cd "$HOME/Krotov-plugin/plugin"
test -e .env || install -m 600 .env.example .env
chmod 600 .env
nano .env
```

Подставьте токен, числовые ID и абсолютные пути к двум созданным каталогам. Папка состояния хранит данные моста и должна быть за пределами рабочей папки Codex.

```dotenv
TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН_ИЗ_BOTFATHER
TELEGRAM_EXPECTED_BOT_ID=ВАШ_BOT_ID
TELEGRAM_ALLOWED_USER_IDS=ВАШ_OWNER_USER_ID
TELEGRAM_ALLOWED_CHAT_IDS=ВАШ_PRIVATE_CHAT_ID
TELEGRAM_STATE_DIR=/ABSOLUTE_STATE_DIR
TELEGRAM_WORKSPACE_ROOT=/ABSOLUTE_WORKSPACE_DIR
KROT_CODEX_APPROVALS=1
# KROT_CODEX_AGENT_NAME="Имя вашего агента"
```

`KROT_CODEX_APPROVALS=1` включает карточки подтверждения в Telegram для действий, до которых Codex запрашивает разрешение. Строки `TELEGRAM_ALLOWED_USER_IDS` и `TELEGRAM_ALLOWED_CHAT_IDS` обязательны в этой инструкции. Обе должны содержать ваш числовой ID, полученный в предыдущем шаге. В nano сохраните файл через **Ctrl+O**, **Enter**, затем **Ctrl+X**.

### Режим карточек для рискованных команд

Для новой установки выберите `./install.sh --approval-mode risky --start`. Для уже запущенного бота выполните `./install.sh --approval-mode risky`, затем перезапустите службу моста, когда бот свободен.
При ручной настройке добавьте `KROT_CODEX_APPROVAL_MODE=risky` рядом с `KROT_CODEX_APPROVALS=1` в `plugin/.env` и перезапустите мост. Чтобы вернуться к обычным карточкам Codex, выберите `--approval-mode standard` или укажите `KROT_CODEX_APPROVAL_MODE=standard`.

Режим автоматически принимает однократные запросы Codex на известные диагностические команды, например `df -h`, `free -m`, чтение статуса службы и ограниченный вывод журнала конкретной пользовательской службы. В составной строке каждая команда должна подходить под правила диагностики. При запросе Codex на потенциально опасную или неясную команду карточка остаётся. Сеть, ввод в терминал и изменения файлов проходят обычную обработку подтверждений.

Мост работает от пользователя службы и сохраняет песочницу Codex. Режим применяется к запросам разрешений от Codex, а при подключённом совместимом YAML-хуке также помечает известные опасные команды до запуска. Поведение команд, уже разрешённых пользовательскими правилами Codex или песочницей без хука, задаёт сам Codex.

### Подтверждения MCP

Подключите нужный MCP-сервер в профиле Codex того пользователя Linux, от которого запущен мост. Установщик включает карточки через `KROT_CODEX_APPROVALS=1`. Когда Codex требует подтверждение вызова MCP, в личке появится карточка с именем сервера, инструментом и параметрами операции. Кнопка разрешает один вызов. После ответа параметры сворачиваются, а решение остаётся в сообщении.

Для работы нужен Codex CLI с поддержкой `mcpServer/elicitation/request`. Карточки поддерживают одноразовое согласование вызова. Вход в аккаунт, ввод секретов и другие формы MCP выполняются в штатном клиенте соответствующей службы. Режим `risky` упрощает подтверждения диагностических команд, а разрешениями MCP управляет Codex.

#### Работа с GitHub без карточек

Если владелец выбрал этот режим, укажите `default_tools_approval_mode = "approve"` в разделе `[apps."ВАШ_ID_ПОДКЛЮЧЕНИЯ_GITHUB"]` файла `config.toml` в профиле Codex, который использует мост. Подставьте ID подключённого GitHub из этого профиля. Установщик оставляет выбор владельцу. На обращения через `gh` и `git` действуют правила для команд, а отдельные настройки инструментов могут переопределять режим подключения. [Настройки Codex](https://learn.chatgpt.com/docs/config-file/config-reference)

## 5. Проверьте конфигурацию и получите первый ответ

```bash
cd "$HOME/Krotov-plugin/plugin"
bun run doctor
bun run start
```

Запускайте вторую команду после успешной проверки. `doctor` проверяет одного владельца, каталоги, доступность Codex App Server, локальный статус входа через ChatGPT, соответствие токена ID бота и отсутствие webhook. При ошибке он печатает подсказку и возвращает код 1. Команда обращается к Telegram за данными бота и статусом webhook. Она не читает обновления и не отправляет сообщения.

Оставьте терминал открытым. В личном чате бота отправьте `/help` и затем «Ответь словом КРОТ». Ответ на обычное сообщение проверяет всю цепочку от Telegram до Codex. Когда получите ответ, остановите ручной запуск через **Ctrl+C** перед настройкой автозапуска.

## 6. Включите автозапуск на VPS

Остановите ручной запуск. Затем выполните команды из корня своего клона. Установщик использует ваше окружение и уже заполненный `plugin/.env`.

```bash
cd "$HOME/Krotov-plugin"
./install.sh --start
loginctl show-user "$(id -un)" -p Linger
```

Если установщик попросит разрешить работу службы после выхода из терминала, выполните `sudo loginctl enable-linger "$(id -un)"` и повторите установку с `--start`. В последней строке ожидайте `Linger=yes`. Проверьте ответ бота после выхода из терминала.

Для обслуживания введите имя службы, указанное установщиком.

```bash
read -r -p 'Имя службы: ' krotov_unit
systemctl --user status "$krotov_unit" --no-pager
journalctl --user -u "$krotov_unit" -n 50 --no-pager
```

Для перезапуска после изменения `.env` выполните `systemctl --user restart "$krotov_unit"`. Если `systemctl --user` не видит шину пользователя, подключитесь к серверу напрямую под пользователем моста.

### Перезапуск моста из Telegram

Для установки под systemd добавьте `KROT_CODEX_SELF_RESTART=1` в `plugin/.env` и примените настройку при ближайшем перезапуске службы. Штатный юнит использует `Restart=on-failure`. При явной просьбе владельца перезапустить мост плагин сначала доставляет итог, дожидается пустой очереди и предупреждает в личке. Попросите также проверить результат после перезапуска, чтобы агент продолжил проверку в том же диалоге при локальном запуске Codex App Server.

Отправьте боту отдельное сообщение «Перезапусти Telegram-мост и после перезапуска проверь связь». Если идёт задача, мост выполнит перезапуск после неё.

## Если бот не отвечает

| Что видно | Что проверить |
|---|---|
| Codex или Bun не найден | Выполните `export PATH="$HOME/.bun/bin:$HOME/.local/bin:$PATH"` в текущем SSH-терминале. Для службы проверьте `PATH` в файле службы. |
| Telegram вернул `401` | Сверьте токен с BotFather и повторите `bun run doctor`. |
| Telegram вернул `409` | Проверьте, что с этим токеном не работает второй экземпляр и webhook отключён. |
| `doctor` проходит, но `/help` молчит | Проверьте ID владельца по шагу 3, убедитесь, что пишете в личку нужному боту, и посмотрите журнал моста. |
| `/help` работает, обычное сообщение не получает ответа | Проверьте `codex login status` от пользователя службы и сообщения Codex в журнале. |
