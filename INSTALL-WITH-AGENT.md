# Установка своего Telegram-агента с помощью Codex

Отправьте своему агенту ссылку на репозиторий и напишите:

> Установи Krotov-plugin на мой Linux VPS и подключи к моему боту в Telegram. Следуй INSTALL-WITH-AGENT.md, сам выполняй команды и доведи установку до первого ответа. Сообщи, когда от меня понадобится вход в аккаунт или действие в Telegram.

Нужны VPS с Ubuntu или Debian и systemd, доступ по SSH, аккаунт ChatGPT с Codex и доступ к репозиторию. Имя, профиль, бот и рабочие данные у каждого владельца свои.

## Инструкция для агента

Выполняй шаги на VPS через SSH под обычным пользователем будущей службы. Текущий чат оставь открытым как канал связи на случай, если Telegram-бот ещё не заработал. Начни с адреса или SSH-алиаса VPS и имени пользователя, если эти сведения ещё неизвестны. Узнай, как назвать агента, только если владелец хочет имя, отличающееся от имени бота.

Пользователь входит в свои аккаунты сам. Попроси его подтвердить вход в браузере или ввести токен в скрытом терминале. Пароли, коды входа, приватные ключи и токены не нужны в чате агента. Если секрет уже лежит на VPS в файле с правами `600`, запроси только путь к нему. Не выводи этот файл и не передавай секрет через аргумент команды.

### 1. Подготовь Linux VPS

1. Проверь SSH, обычного пользователя и пользовательский systemd. Если доступ есть только под `root`, помоги создать отдельного пользователя и войти под ним. Действия администратора выполняй в пределах предоставленного доступа.
2. Установи недостающие зависимости. Используй системный пакетный менеджер для `git`, `curl`, `jq`, `unzip` и сертификатов. Для приватного репозитория может понадобиться `gh`. Bun и Codex CLI устанавливай от пользователя службы по официальным инструкциям. Проверь `bun --version` и `codex --version`. [Bun](https://bun.com/docs/installation) · [Codex CLI](https://learn.chatgpt.com/docs/codex/cli)
3. Клонируй репозиторий по ссылке владельца в отдельную папку. Для приватного репозитория используй уже настроенный доступ. Если GitHub просит вход, начни `gh auth login --hostname github.com --git-protocol https --web`, попроси владельца подтвердить вход в браузере, затем выполни `gh auth setup-git`. Сохрани текущую видимость репозитория.
4. Проверь `codex login status` под пользователем службы. Если необходим вход, запусти `codex login --device-auth` в интерактивном терминале и дождись, пока владелец завершит его в браузере. Вход в настольное приложение на ПК и вход в Codex CLI на VPS выполняются отдельно. [Вход на VPS](https://learn.chatgpt.com/docs/auth#login-on-headless-devices)

### 2. Свяжи личку Telegram

Попроси владельца создать своего бота в [BotFather](https://t.me/BotFather), если у него ещё нет бота. Для обычной установки лучше начать с нового токена. При переиспользовании существующего бота сначала выясни, какая служба им владеет.

В корне рабочего клона выполни `./install.sh --dry-run --start`, затем выбери способ безопасного ввода:

- Если владелец может ввести токен в открытом SSH-терминале, запусти `./install.sh --start` и дай ему ввести токен скрыто. Установщик напечатает одноразовый код. Владелец нажимает **Start** в личке нужного бота, отправляет этот код и подтверждает отправку в терминале.
- Если токен уже в защищённом файле на VPS и владелец знает свой числовой ID Telegram, выполни `./install.sh --non-interactive --token-file /абсолютный/путь --owner-id ID --start`.
- Если токен уже в защищённом файле, а ID неизвестен, создай новый код на VPS командой `printf 'krotov-%s\n' "$(cat /proc/sys/kernel/random/uuid)"`. Назови владельцу бота по имени пользователя, выбранному в BotFather, и передай только этот код. Когда код отправлен в личку бота, выполни `./install.sh --non-interactive --token-file /абсолютный/путь --pair-code КОД --start`. При необходимости добавь `--agent-name "Имя"`. По умолчанию используется видимое имя бота.

Новая установка по умолчанию работает автономно, без карточек подтверждения (`--approval-mode never`). Если владелец хочет подтверждать действия за пределами рабочей папки, добавь `--approval-mode standard`. Если владелец попросил карточки только для опасных команд, добавь `--approval-mode risky` к выбранной команде установки. Для работающего бота выполни `./install.sh --approval-mode risky` (или `standard`, `never`) и перезапусти `krotov-telegram.service`, когда бот закончит текущую работу.

Если владелец попросил GitHub без карточек или проверку после перезапуска, включи выбранный режим по инструкции. [GitHub](plugin/docs/quickstart.md#работа-с-github-без-карточек) · [Перезапуск моста](plugin/docs/quickstart.md#перезапуск-моста-из-telegram)

Установщик проверяет бота, создаёт приватный `plugin/.env`, рабочую папку, состояние и начальный `AGENTS.md`. Существующие профиль и настройки сохраняются. Если `loginctl` потребует администратора, включи linger для пользователя службы в пределах выданных прав и повтори `./install.sh --start`.

### 3. Проверь, что установка завершилась

1. Подтверди, что `bun run doctor` из `plugin/` прошёл, а `systemctl --user is-active krotov-telegram.service` вернул `active`.
2. Проверь в личке этого бота `/help` и обычным сообщением «Ответь словом ГОТОВО». Если у тебя есть доступ к чату, которым владелец разрешил воспользоваться, сделай проверку сам. Иначе попроси его отправить только эти два сообщения и дождись подтверждения обычного ответа. Так проверяется путь Telegram → Codex → Telegram.
3. Сообщи владельцу имя и `@username` его бота, расположение `AGENTS.md` для настройки характера и команды просмотра журнала. Установка завершена после обычного ответа, а при блокере укажи, какой шаг ещё ждёт владельца.

Для обновления выполни `./update.sh` из того же клона. Когда бот свободен, перезапусти пользовательскую службу через SSH или используй `./update.sh --restart` из отдельного сеанса. Для ручной установки и разбора ошибок есть [пошаговая инструкция](plugin/docs/quickstart.md).
