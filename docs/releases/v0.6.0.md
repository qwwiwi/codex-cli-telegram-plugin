# v0.6.0 · 2026-11-28

This release improves multi-user history recovery, bridge updates, and Telegram reply diagnostics.

## English

- The bridge creates fresh Codex homes for members and guests at startup and copies eligible thread history. If some history cannot be read, the bridge keeps its source and retries on the next start. The cleanup process removes old login copies and retires old homes, including runtime links and sockets. `/doctor` reports copy failures, quarantined homes, and damaged generation records that stop cleanup.
- Roles stay available if a successful hook check cannot be saved. `/doctor` reports the write failure and the bridge repeats the check at the next start.
- The state directory needs a file system with hard-link support for multi-user mode. If startup reports that hard links are unavailable, move the state directory to a file system that supports them or turn off `KROT_MULTIUSER`.
- If you roll back to v0.5, that version cannot see chats saved in `codex-public/generations/`. A later upgrade resumes from those generations and does not import chats written by v0.5 during the rollback.
- `/update` and startup recovery share one lock per checkout. The lock stays held throughout recovery and is released even if a child process outlives it. `/update` reports a missing `flock` utility or a lock error separately from an update in progress.
- New reply plans mask values that become visible only after formatting is removed. Plain-text fallbacks mask across message boundaries and split masked text that exceeds Telegram's message limit.
- Render diagnostics use the text or document body sent to Telegram. The bridge removes old reply excerpts from render history and moves corrupt history files aside with a warning. Editing a Rich Message also updates its preview.

## Русский

- При запуске мост создаёт новые папки Codex для участников и гостей и переносит доступную историю их чатов. Если часть истории не удаётся прочитать, мост сохраняет исходную папку и повторяет перенос при следующем запуске. Очистка удаляет старые копии данных входа и прежние папки ролей вместе с созданными Codex ссылками и сокетами. `/doctor` показывает ошибки переноса, папки в карантине и повреждённые записи, из-за которых остановилась очистка.
- Роль остаётся доступной, если результат успешной проверки хука не удалось сохранить. `/doctor` показывает ошибку записи, а при следующем запуске мост повторяет проверку.
- Для многопользовательского режима нужна файловая система с поддержкой жёстких ссылок в папке состояния. Если мост сообщает об их отсутствии, перенесите папку состояния на подходящую файловую систему или выключите `KROT_MULTIUSER`.
- После отката на v0.5 чаты из `codex-public/generations/` недоступны этой версии. При повторном переходе на v0.6 мост продолжит работу с этими папками. Чаты, записанные v0.5 после отката, в них не появятся.
- `/update` и восстановление при запуске используют одну блокировку на копию репозитория. Блокировка держится до конца восстановления и освобождается, даже если дочерний процесс продолжает работать. `/update` отдельно сообщает об отсутствии `flock`, ошибке блокировки и уже идущем обновлении.
- При подготовке новых ответов мост скрывает значения, которые становятся видимыми после удаления разметки. При отправке обычным текстом мост скрывает значения на границах сообщений и разбивает текст, если после маскировки он превышает лимит Telegram.
- Диагностика отображения использует отправленный текст или содержимое документа. Мост удаляет старые отрывки ответов из истории диагностики, а повреждённые файлы истории откладывает отдельно и пишет предупреждение. Правки форматированных сообщений Telegram также обновляют их предпросмотр.
