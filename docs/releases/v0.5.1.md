# v0.5.1 · 2026-11-27

Fixes for issues reported by the community (#12, #13, #14, #15, #16, #17, #18, #20, #21). Thank you, @martinmute.

## English

- Updates no longer fail on a loaded server: the staged test run in `update.sh` and automatic update uses a 60-second per-test timeout (`KROT_UPDATE_TEST_TIMEOUT_MS`). A failing test still blocks the update. (#20)
- Several agents under one Linux user: `install.sh --service-name NAME` gives each copy its own systemd service. If an existing service belongs to another checkout, the installer stops with a clear message instead of reusing it. The default name stays `krotov-telegram.service`. (#18)
- Inter-agent mail: the sender is recognised in both header forms (`[Inter-agent от X → Y]` and `[Inter-agent from X -> Y]`). The owner notice is one clean line by default; `KROT_AGENT_WEBHOOK_OWNER_NOTICE=full|brief|off` controls it, and `off` sends nothing to the owner. (#17, #21)
- A link to a local file is shown as a code path and no longer drops the formatting of the whole reply. (#14)
- `/mirror` shows one line per command, never raw command output, and collapses when the turn ends. (#15)
- After Telegram refuses widgets for a bot, the bridge stops sending them until restart, and `/doctor` says whether widgets are available. (#16)
- `/doctor` warns when approvals are off and an MCP server lacks `default_tools_approval_mode = "approve"`; the install guide explains it. (#12)
- The known-problems map explains why `systemctl status` fails inside the workspace-write sandbox. (#13)

## Русский

- Обновление больше не падает на нагруженном сервере: тесты в отдельной копии идут с таймаутом 60 секунд на тест (`KROT_UPDATE_TEST_TIMEOUT_MS`). Упавший тест по-прежнему не пускает обновление. (#20)
- Несколько агентов под одним пользователем: `install.sh --service-name ИМЯ` даёт каждой копии свою службу. Если служба принадлежит другой копии, установщик останавливается с понятным сообщением. Имя по умолчанию прежнее – `krotov-telegram.service`. (#18)
- Почта между агентами: отправитель распознаётся в обоих видах заголовка. Уведомление владельцу – одна чистая строка; `KROT_AGENT_WEBHOOK_OWNER_NOTICE=full|brief|off` управляет им, `off` ничего не шлёт. (#17, #21)
- Ссылка на локальный файл показывается как путь в коде и не ломает форматирование ответа. (#14)
- `/mirror` показывает по строке на команду, без сырого вывода, и сворачивается после хода. (#15)
- Если Telegram не принимает виджеты для бота, мост перестаёт их слать до перезапуска, а `/doctor` показывает, доступны ли они. (#16)
- `/doctor` предупреждает, когда подтверждения выключены, а у MCP-сервера нет `default_tools_approval_mode = "approve"`; это описано в инструкции по установке. (#12)
- Карта известных проблем объясняет, почему `systemctl status` не работает в песочнице workspace-write. (#13)
