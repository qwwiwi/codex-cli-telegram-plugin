# v0.6.1 · 2026-11-28

This release improves masking in Telegram replies and makes tables and components readable as text.

## English

- The bridge masks exactly the text you see in Telegram, even when formatting splits a protected value or character codes hide it. If a link label or destination contains a protected value, the label appears without a clickable link. Masking also covers edits, guest answers, and photo and document captions.
- A multi-message reply is saved as one entry. After a restart or rate-limit wait, the bridge resumes after the last sent message and masks newly registered values, including values that cross the boundary between messages. It migrates and masks existing queued replies on first start. If Telegram rejects the formatting, the bridge retries once with the same text as plain text.
- Tables and other Rich Message elements arrive in regular text messages. Tables use aligned monospace columns and plain text inside each cell. Rich Message edits arrive as text edits. Existing configurations still load when they contain the `richMessages` block, which now has no effect.
- `send_component` delivers the text version of charts, diagrams, and cards.
- `/doctor` puts damaged generation paths and the boot guard warning before verbose journal entries. When the file system lacks hard-link support, the startup console shows the cause and remedy ahead of the potentially long state path. Refreshing the installed boot guard keeps its permissions at `0600`.
- Known limitation. A value registered after a reply was prepared may stay unmasked in the local queue file until the file is next saved.

## Русский

- Мост маскирует именно тот текст, который виден в Telegram, даже если значение разделено разметкой или задано кодами символов. Если защищённое значение есть в подписи или адресе ссылки, подпись отображается без активной ссылки. Маскировка также действует при правках сообщений, в гостевых ответах и в подписях к фотографиям и документам.
- Ответ из нескольких сообщений сохраняется одной записью. После перезапуска или ожидания из-за лимита Telegram мост продолжает отправку с места остановки и маскирует новые значения, даже если они пересекают границу сообщений. При первом запуске мост переносит и маскирует уже ожидающие ответы. Если Telegram отклоняет форматирование, мост один раз повторяет отправку того же текста без форматирования.
- Таблицы и другие элементы Rich Messages приходят в обычных текстовых сообщениях. В таблицах выровнены столбцы, а ячейки содержат обычный текст в моноширинном блоке. Правки Rich Messages отправляются как правки текстовых сообщений. Конфигурации с блоком `richMessages` по-прежнему загружаются, но этот блок больше ни на что не влияет.
- `send_component` отправляет текстовую версию графиков, диаграмм и карточек.
- `/doctor` показывает пути к папкам с повреждёнными записями и предупреждение о скрипте восстановления до подробностей журнала. Если файловая система не поддерживает жёсткие ссылки, при запуске причина и решение выводятся перед путём к папке состояния, который может быть длинным. При обновлении скрипта восстановления сохраняются права `0600`.
- Известное ограничение. Значение, зарегистрированное после подготовки ответа, может оставаться незамаскированным в локальном файле очереди до следующего сохранения файла.
